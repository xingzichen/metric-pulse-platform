# Metric Pulse Platform 需求与技术方案一致性回检

- 回检日期：2026-08-24
- 增量回检：2026-08-26（抓取最终失败的人工处置闭环）
- 基线：需求文档 V2.4、技术方案 V2.4、系统/应用设计 v1.6
- 范围：金标边界、P0-3 状态语义、P0-2 吞吐与恢复、P0-4 异常审核、直链优先路由、验收口径

## 结论

本轮文档回检后，未发现会阻断按 `P0-3 → P0-2 → P0-4` 实施的未决需求冲突。已发现的口径冲突均已统一为下表中的决策。

截至 2026-08-24 本轮实施结束，下表决策已完成代码、迁移、API/UI 和回归落地。验收报告中历史已通过结果仅保留为当时管线/Excel 重建事实，不作为采集准确率证据。

## ADR-0006 增量冲突回检

1. “直链优先”与“每行都搜索”的旧要求直接冲突，已明确由用户的新业务要求和 ADR-0006 取代旧要求；搜索仍逐行隔离，但变为条件降级。
2. “相同来源复用上下文”不等于“模型复用会话”：只复用不可变原文、解析索引和当前行有界切片，每行保持两个全新独立模型请求，因此与禁止模型批处理、避免跨行误解兼容。
3. 直链确定性匹配不会跳过模型。唯一结构化匹配仍作为本行证据完成 `SYNTHESIZE` 与 `VERIFY`，因此与固定双阶段质量契约不冲突。
4. OMLX 前缀缓存是机会性加速，不作为业务缓存或结果复用；缓存开关不影响结果，因此与行隔离和可复现性兼容。
5. 金标仍只属于外部测试/验收。历史影响扫描依据生产审计中的输入链接、选中来源和确定性匹配差异，不读取金标，因此不改变生产边界。
6. 常规升级优先等待在途单元自然结束；本次任务因字段契约整体失效，用户已明确授权丢弃进度
   并直接停止服务，因此不恢复旧任务，也不要求为错误规划保留执行现场。

结论：除已由 ADR-0006 显式取代的“每行固定先搜索”外，未发现与状态语义、双阶段模型、OMLX 并发 1、审核门禁或金标隔离的新冲突。代码实施门禁为：先完成路由审计与契约测试，再迁移副本、回归和缓存基准，最后升级本地服务并恢复任务。
5. P0-4 通过策略审计、抽样熔断、批量冲突和未解决报告验收后，再继续后续整表与生产化工作。

## ADR-0007 增量冲突回检

1. “`be_data/data` 等价”与最新业务语义直接冲突，统一删除等价复制路径。
2. “每行固定两次模型调用”与“程序失败后模型降级”不冲突：转换候选包含在原有两次调用中，
   程序转换成功时忽略模型候选，绝不新增第三次请求。
3. `be_unit` 已有历史值不代表本次来源事实，只能作为提示；因此 ai_index 不能继续使用通用
   “只采空字段”规划，必须原子重采原始值/单位和标准值。
4. `unit` 是目标标准，不属于模型采集字段。目标单位为空时只允许使用已确认的唯一配置；
   否则保留原始观测并进入部分解决/人工工具。
5. 单位注册表由现有业务表的单位种类和转换对沉淀，不读取任何金标结果值，生产边界不变。
6. 旧任务已按用户授权直接停止。由于字段语义改变，完成实现后清空旧运行数据并从空表重跑，
   不进行平滑迁移。

实施结果：ai_index 专用规划稳定包含 `be_data、be_unit、data`，缺少输入链接时同时包含
`source_url`；联合约束进入不可变 RowContract；程序注册表覆盖当前表已出现的单位族；两个
单位同时为空的无量纲指标执行倍率 1 的确定性恒等转换；人工修正原始值/单位时后端重新生成
`data`，前端将该字段设为只读并展示公式、规则版本、约束匹配和来源链路。

结论：ADR-0007 与直链优先、双阶段单模型、全局并发 1、来源门禁和金标隔离兼容；它取代
当前实现中的等价值复制，并把文档中未落地的“确定性单位复算”变成可验收的程序契约。

## ADR-0008 增量冲突回检

1. “所有仓库”定义查询全集，不表示全部写入；每次只输出排序后的前 10 名。
2. 该表的固定搜索页已经是业务来源，不能套用通用“无直链逐行搜索”或失败后 SearXNG
   降级；等价 GitHub API 只是结构化获取适配器，工作簿仍记录固定网页地址。
3. 增量语义要求保留历史行，因此不能刷新已有样例，也不能用历史行数量决定本次单元数。
4. 确定性程序负责完整快照、排序、名次、整数 `k` 换算和固定元数据；模型仍按每行两次请求
   核验来源事实，不减少全局双阶段质量门禁。
5. 来源正文可以缓存，但十个名次各自使用一行有界证据和新会话，不会把多个项目放入同一
   模型上下文；这与 OMLX 全局并发 1 完全兼容。
6. 任务规划时冻结一个当前时间，保证三类时间和十行快照一致；执行耗时不会造成跨时点榜单。
7. 当前旧任务已按用户授权停止且无需保留进度；完成回归后清空运行数据并从原始空表重建。

结论：未发现与 ADR-0006/0007、状态语义、审核门禁或金标隔离的未决冲突。ADR-0008 作为
该工作表的专用 Profile，优先于通用工作簿识别、通用直链降级和逐已有行规划规则。

## ADR-0009 增量冲突回检

1. 当前实现把 `top_list_ai` 当作已有行补空，与年度增量需求冲突；以 ADR-0009 的
   `annual_top50_append` 取代。
2. 福布斯 2026 AI 50 官方口径是 50 家、按字母顺序、无排名。“Top 50”不能被实现为
   `1..50` 业务排名；内部位置只负责稳定切片和完整性校验。
3. 固定来源与通用搜索降级冲突；该表必须官方来源失败关闭，不能用转载页补字段。
4. 一次快照复用与行隔离兼容：只复用不可变官方正文和结构化索引，50 家公司仍分别构造
   有界证据，并各自固定执行两次全新模型请求。
5. 确定性融资换算与固定双模型兼容：程序换算优先，模型只核验来源事实；不支持格式的降级
   候选占用既有两阶段，不增加第三次调用。
6. 历史活动批次切换属于正式导出事务，不能在规划、执行或未完整审核时提前改写原工作簿；
   因此与审核门禁和可恢复执行兼容。
7. 同年度官方完整批次按“年度 + 固定官方来源”幂等；当前模板中的非官方 2026 批次不构成
   幂等命中，必须追加新 50 行并在正式导出时将旧批次标记为删除。
8. 金标仍只存在于生产系统之外的测试/验收环境；Profile、模型提示、缓存、数据库和导出逻辑
   均不读取或推断金标。

结论：除明确由 ADR-0009 取代的通用行补空、搜索降级和隐含排名外，未发现与既有状态语义、
审核门禁、全局单模型串行、双阶段模型或金标隔离的未决冲突。代码实施顺序为：Profile 与规划
→ 官方快照解析/严格 50 条门禁 → 确定性单位换算与逐公司双模型 → 幂等和导出批次切换 →
前端审核展示与全量回归。
