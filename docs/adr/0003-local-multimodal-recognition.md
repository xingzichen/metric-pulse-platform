# ADR-0003：本地多模态模型识别架构

## 状态

已提议，待视觉合约和平台外部测试集刺探通过后接受。

## 背景

本地 OMLX 中的 `Qwen3.8-27B-6bit` 已确认支持图像识别和图像理解。旧 `metric-pulse-service` 的识别主要包含两条路径：

1. Excel 识别依赖写死的 `DATASET_PROFILES`、Sheet 名前缀，并仅在前两行查找 `logic_id`；
2. 网页图片先经 Sharp 灰度、增强、二值化和模糊预处理，再使用 Tesseract 抽取纯文字。

第一条路径无法处理未知工作簿和灵活多层表头；第二条路径丢失图表、表格、标签关系和业务语义。但如果只把工作簿截图交给模型，又会失去单元格原始值、公式、精确坐标和可重放性。

## 决策摘要

新系统抛弃旧硬编码 Excel 识别和 Tesseract OCR 主路径，但不抛弃确定性文件解析。统一采用：

```text
原始文件/图片
  → 确定性解析与安全检查
  → 可追溯渲染图/分片
  → 本地多模态模型生成结构化候选
  → 程序交叉校验
  → 自动接受或仅将冲突交给人确认
  → 确认结果版本化为可复用模板
```

这是“模型识别为主的语义层 + 确定性解析为事实层”，不是纯视觉端到端写回。

## 详细决策

### 1. 工作簿事实层

`StructureExtractor` 使用 openpyxl 和必要的 OOXML 底层读取生成 `WorkbookStructureGraph`，至少包含：

- Sheet 名称、顺序、显示/隐藏状态和 used range；
- 单元格 A1 坐标、原始值、显示值、数据类型、公式和样式引用；
- 合并区域、行高、列宽、冻结窗格、过滤器、数据验证和表对象；
- 空值分布、类型分布、公式延展和样式簇等派生特征。

任何模型结论不得覆盖事实层。例如，模型认为标题位于 `B2`，但该坐标不存在或值不匹配，该候选必须失败。

### 2. 可追溯渲染层

`SheetRenderer` 为每个参与处理的 Sheet 生成：

- 一张保留整体版式的缩略图；
- 若干张高清分片，分片记录 Sheet 坐标边界；
- 可选的行列坐标覆盖层，供模型和人工定位；
- 渲染器版本、DPI、字体替代、工作簿 hash 和图片 hash。

渲染图是证据快照，不是单元格值的事实来源。

### 3. 多模态语义层

`VisionRecognizer` 与文本采集共用唯一的本地模型 `Qwen3.8-27B-6bit`。任务和运行配置不提供模型 alias 选型、备用模型或降级路径。管理配置只记录和验证：

- 实际模型标识、量化和配置修订；
- `vision`、`structured_output` 和允许的 MIME 能力；
- 最大图片数、像素、请求体、上下文和输出长度；
- 超时、固定全局并发 1 和优先级。

工作簿识别 Schema 输出：

- Sheet 的业务目的和建议 mode；
- 表头行范围、数据区域和预留区域；
- 字段名称、中文语义、类型和定位坐标；
- descriptor fields、target groups 和 business-key candidates；
- 必需约束、空值语义和简短可审计理由；
- 歧义、备选项和需要人工确认的问题。

网页/PDF/附件图片识别 Schema 按采集目标定制，输出文字块、表格单元、图表标签、语义候选和对应分片坐标。

### 4. 融合与门禁

`RecognitionFusion` 将以下独立信号组合：

- 已发布模板的结构签名相似度；
- OOXML 事实层约束；
- 视觉模型候选；
- 字段类型分布、唯一性、空值率和公式依赖；
- 同一输入不同分片或必要复核请求的一致性。

自动接受必须同时满足：

1. 所有坐标和区域在 OOXML 事实层中存在且不非法重叠；
2. 每个必需 descriptor/target/business-key 字段都可定位；
3. 结构规则、模板和模型之间没有关键冲突；
4. 业务键在样本行中满足唯一性和空值要求；
5. 联合置信使用独立离线测试集校准后的阈值；平台运行时只读取已发布阈值，不读取该测试集。

其他情况进入 `NEEDS_CONFIRMATION`。模型自报 confidence 只是一个弱特征，不是门禁本身。

### 5. 模板是已确认知识，不是硬编码

用户对新工作簿的修正可保存为草稿模板版本，发布后才可为后续任务自动复用。模板保存：

- 结构签名和允许差异；
- 字段角色、RowContract、业务键和目标组；
- 验证、导出和来源策略；
- 确认人、来源 recognition attempt 和发布审计。

模板应存储在数据库并版本化，不在 Python 代码中继续添加按 Sheet 名分支。

### 6. 图片证据主路径

新系统不将 Tesseract 纳入首版核心依赖。使用本地多模态模型直接理解图片中的文字、表格、标签关系和业务语义。但仍保留图片解码、缩放、切片、方向纠正和安全检查，它们是输入治理，不是识别引擎。

如后续外部测试表明大批纯文本扫描使用专用 OCR 更快或更准，可在 `MediaRecognizer` 端口下增加可选 OCR 快速路径，但其输出必须与模型输出遵守同一证据和 Schema 契约。

### 7. 资源和优先级

工作簿创建向导对识别延迟敏感，采集任务对总吞吐敏感。OMLX Gateway 设置：

- `interactive-vision`：上传预览和审核页手动重试，高优先级；
- `evidence-vision`：网页/PDF 图片证据，普通优先级；
- `text-collection`：文本候选抽取，普通优先级；
- 所有分类共享同一全局串行队列，在途请求始终不超过 1；分类只决定排队优先级，不产生并发或批处理。

已发布模板精确命中时可跳过完整视觉识别，只运行差异检查。这是降低日常运行成本和人工成本的主要快速路径。

## 失败与降级

| 场景 | 处理 |
| --- | --- |
| 视觉能力探测失败 | 标记 capability unavailable，禁用新结构自动接受，已发布模板仍可走确定性快速路径 |
| 图片过大或过长 | 等比缩放和重叠分片，保留分片坐标 |
| 模型输出不符合 Schema | 有界重试一次，仍失败则转人工/替代来源 |
| 坐标不存在或越界 | 不尝试猜测修复，记录冲突并转 `NEEDS_CONFIRMATION` |
| 模型与发布模板冲突 | 展示结构 diff，用户选择沿用、升级模板或另建模板 |
| OMLX 运行中断 | attempt 可重试；不把“未识别”当作“无数据” |
| 6-bit 量化更换或模型升级 | 视为新 model revision，由独立验收环境重跑外部测试后才允许自动接受 |

## 安全与隐私

- 工作簿和来源图片只发送到管理员配置的本地 OMLX endpoint；
- 图片对象通过内部字节或短时签名 URL 提供，不对公网暴露对象存储；
- 网页图片在下载前继续执行 SSRF、MIME、尺寸、解码和解压炸弹检查；
- Prompt 将文档中的指令视为不可信数据，模型无工具执行权限；
- 原始图片和识别响应遵守任务数据保留策略。

## 外部验收测试集

编码前先建立两类离线 Fixture：

### 工作簿识别集

- 275 行快速回归文件；
- 完整 11 Sheet 输入与外部期望结果，仅供独立验收器使用；
- 变体：Sheet 改名、表头上移/下移、额外说明行、列重排、合并单元格变化、隐藏列和空表；
- 若干经脱敏的新工作簿样本。

关键验收：

- 已发布模板精确命中的结构解析与字段映射必须 100% 一致；
- 新结构的关键字段错误不得静默进入任务；
- 表头区域、数据区域、descriptor fields、target groups 和业务键分别统计准确率与转人工率；
- 门禁阈值优先消除静默错误，再逐步降低人工确认率。

### 图片证据集

- 中英文纯文字图片；
- 榜单、复杂表格、图表、网页海报和 PDF 渲染页；
- 低分辨率、长图、旋转、深/浅底和噪声变体。

按任务 Schema 评估字段精确率、完整率、证据定位可用率和人工修正率，不只评估通用 OCR 字符正确率。

## 被否决或推迟的方案

### 继续使用硬编码 Dataset Profile

否决。它只能处理已知 Sheet，且每个新工作簿都需要修改代码和发布。已确认结构改为数据库中的版本化模板。

### 继续使用 Tesseract 作为默认图片识别

首版否决。它只提供文字识别，无法直接解释图表、表格和标签关系，同时引入一套额外模型和语言数据运维。保留未来根据外部测试结论添加专用 OCR 快速路径的选项。

### 纯模型端到端识别并直接写回

否决。模型无法成为 OOXML 坐标、公式和原始值的事实来源，且量化、Prompt 和模型版本变更会改变结果。

### 每次上传都运行完整视觉识别

否决。已发布模板精确命中后应走结构差异快速路径，否则会无必要地增加 OMLX 等待时间和结果波动。

## 后果

### 正面

- 新工作簿不需开发人员为每个 Sheet 写代码；
- 图片证据从纯文字 OCR 升级为文本、表格和语义联合理解；
- 数据不离开局域网本地模型服务；
- 人工确认可沉淀为模板，日常运行逐步越来越少人工。

### 代价与风险

- 27B 6-bit 视觉请求占用本地计算资源，需要分类排队和全局并发限制；
- 工作表渲染受字体和 LibreOffice 版本影响，必须记录渲染版本；
- 模型和量化更换可能造成识别回归，必须先由独立验收环境跑外部测试；
- 结构与视觉融合比单一 OCR 更复杂，但它把复杂性集中在一个可测试边界内。

## 技术刺探通过条件

1. OMLX OpenAI 兼容接口能接收图片并稳定返回约定 JSON Schema。
2. 同一图片和同一参数重复请求的关键字段结果稳定；温度默认为 0 或服务支持的最低值。
3. 275 行工作簿可正确识别 11 个 Sheet、表头、数据区、descriptor fields 和 target groups。
4. 外部变体测试集中没有错误关键映射静默进入任务。
5. 网页图片集的任务字段精确率和人工修正率明显优于旧 Tesseract 基线。
6. 视觉队列满载时，文本采集、API 和任务控制仍可用。
