# ADR-0009：福布斯 AI 50 年度增量采集

- 状态：Accepted / Implemented
- 日期：2026-08-24
- 适用工作表：`top_list_ai` / TOP50 企业排名

## 背景

该工作表是年度增量名单，不是对既有行逐字段补空。每次采集应从福布斯官方 AI 50 页面
取得当前年份完整名单，并在新的空白区域追加 50 行。生产系统不得读取或推断外部金标。

固定业务来源为：

`https://www.forbes.com/lists/ai50/`

福布斯明确说明榜单按公司名称字母顺序展示且不设名次。因此内部可使用页面位置 `1..50`
完成证据切片、完整性校验和逐公司处理，但不得把该位置写成业务排名。

## 决策

1. `rank_year` 使用任务规划时的 Asia/Shanghai 当前年份；本次任务为 2026 年。
2. 程序对固定官方页面获取一次年度快照，必须解析出恰好 50 家名称唯一的公司以及官方发布
   时间。少于或多于 50 家、重复、关键结构缺失或年份不匹配时失败关闭。
3. 只允许福布斯官方页面作为事实来源。固定页面失败或字段缺失时不得使用 SearXNG、转载页或
   其他来源拼凑；对应单元进入重试或未解决/人工核对。
4. 每家公司只生成一行有界证据和一个独立 RowContract，使用全新消息串行执行
   `SYNTHESIZE -> VERIFY` 两次 `Qwen3.8-27B-6bit` 请求。禁止模型批处理、跨公司会话、
   候选/结论复用和并发。
5. 模型核验公司、总部所在地、首席执行官、官方融资原文和成立年份；程序负责名单完整性、
   当前年份、官方发布时间、固定元数据、融资单位换算、逻辑 ID 和新旧批次状态。
6. 融资额统一写为 `亿美元`。程序优先确定性解析福布斯常见的 `$<number> BIL` 与
   `$<number> MIL`：BIL 乘以 10，MIL 乘以 0.01；使用 Decimal 避免浮点误差。
   例如 `$60 BIL -> 600 亿美元`、`$392 MIL -> 3.92 亿美元`、
   `$2.1 BIL -> 21 亿美元`。
7. 不支持的融资格式可在既有两次模型请求中提供降级候选，但不得新增第三次模型调用；没有
   可核验证据时保持未解决，禁止猜测。
8. 同一年度快照冻结一个 `collection_date` 当前时间，50 行完全一致；`datasource_date`
   使用福布斯官方页面发布时间；`update_time/created_time` 等未列字段保持空白。
9. 新批次固定写 `source=福布斯`、固定 `source_url`、`update_frequency=year`、
   `data_type=采集`、`data_status=新增`。
10. `logic_id` 由“年度 + 规范化公司名称”确定性哈希生成。同一工作簿中已存在当前年度、
    同一官方来源的完整 50 行批次时不得再次追加，以“年度 + 固定官方来源”作为批次幂等键。
11. 只有新 50 行均通过导出门禁时，导出程序才把工作簿内此前仍标为 `新增` 的历史活动批次
    改为 `删除`；采集执行和审核过程中不提前修改原工作簿。当前模板应保留 2026 年旧批次，
    在正式导出时将其标记为 `删除`，并把新批次追加到第 203–252 行。
12. 工作簿视觉识别不得覆盖此 Profile 的来源、字段、数量、年度增量模式或官方来源限制。

## 字段契约

| 字段 | 生成方式 |
| --- | --- |
| `logic_id` | 程序按 `sha256(rank_year + "\n" + normalized_company_name)` 生成 |
| `rank_year` | 本次规划时的当前年份 |
| `company_name` | 福布斯官方公司名，逐公司双模型核验 |
| `headquarter_location` | 福布斯官方总部所在地，逐公司双模型核验 |
| `CEO` | 福布斯官方首席执行官，逐公司双模型核验 |
| `financing_amount` | 官方融资原文经确定性程序换算后的数值 |
| `financing_amount_unit` | 固定 `亿美元` |
| `establish_date` | 福布斯官方成立年份，逐公司双模型核验 |
| `source` | 固定 `福布斯` |
| `source_url` | 固定福布斯 AI 50 官方页面 |
| `update_frequency` | 固定 `year` |
| `datasource_date` | 福布斯官方页面发布时间 |
| `collection_date` | 本次任务冻结的当前时间 |
| `data_type` | 固定 `采集` |
| `data_status` | 新批次固定 `新增`；导出时旧活动批次改为 `删除` |

`update_time`、`created_time`、`nextcycle_time`、人员与审核时间字段不是本次采集目标，新追加行
保持空白。

## 冲突与取代关系

- 取代通用 `row_contract_collect` 对该表“逐已有行补空”的推断，固定使用
  `annual_top50_append`。
- 取代当前只采 `financing_amount_unit/source/source_url` 的错误目标识别；完整字段契约以本
  ADR 为准。
- 取代当前复用第 3–52 行历史行的规划方式；新年度批次只写新的空白行。
- 取代固定来源失败后通用搜索降级；缺失字段只能未解决或人工核对。
- “Top 50”表示名单规模，不表示排名；禁止生成福布斯没有发布的业务名次。
- 不改变全局 OMLX 并发 1、每行固定双模型、来源可审计、审核门禁和金标隔离。

## 验收

1. 当前模板正好规划 50 个新单元，目标行是 203–252，既有行在审核完成前不修改。
2. 固定官方页面一次快照必须解析出 50 家唯一公司；每家公司证据只包含自身字段。
3. 每行恰好两次模型调用，所有模型调用全局串行，通用搜索调用为 0。
4. 50 行年度、采集时间、官方来源、更新频次和新增状态一致；官方发布时间一致。
5. BIL/MIL 的 `亿美元` 换算通过 Decimal 确定性测试，不支持格式失败关闭。
6. 完整批准导出后，旧活动批次标为 `删除`、新 50 行标为 `新增`；未全部批准时禁止正式
   导出和旧批次切换。
7. 对已包含同年度官方完整批次的导出工作簿重新规划时新增单元数为 0。
8. 导出后公式、样式、历史行、其他列和其他工作表保持不变。
