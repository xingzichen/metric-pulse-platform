# ADR-0012：最小指标搜索查询与完整契约核验分层

## 状态

已接受，计划随 v1.1.1 交付。

取代范围：ADR-0007 中允许把历史 `be_unit` 用作“搜索提示”的表述；它仍可帮助候选正文中的
来源单位识别和完整契约核验，但不得进入候选发现查询。

## 背景

v1.1.0 的通用搜索查询会同时加入指标名、级别、范围、所有非空地域、统计时间、行业和单位。
2026-08-26 NAS 全量任务的首批 13 次搜索结果全部为 0。查询审计显示，多层地域和业务约束被
搜索引擎当作共同关键词，显著降低了候选召回率。

搜索只负责发现候选，不负责证明候选满足业务口径。把完整 RowContract 塞进搜索词，既重复了
后续核验职责，也会让原本可由正文确认的页面在发现阶段被过早排除。

## 决策

ai_index 搜索查询固定为至多四个词组，按以下顺序组成，指标名不再添加精确短语引号：

1. `index_name` 指标名称；
2. 地域字段中最小的一个非空范围：区县、城市、省份、经济区、宽泛区域；
3. 一个统计时间，规范为“年”“年月”或“年季度”，例如 `2024年`、`2024年6月`、
   `2024年第2季度`；
4. 可选的非空标准单位 `unit`/`standard_unit`，例如 `亿元`、`%`。

不得把 `level`、`scope`、上级地域、`industry`、来源单位 `be_unit`、分类字段或整行 JSON
加入发现查询。非 ai_index 通用表没有 `index_name` 时，可使用原有主体字段中的第一个非空值；
固定 GitHub 与 Forbes Profile 继续只使用绑定的权威来源，不进入搜索降级。

每次搜索把策略版本、主体字段、选中的地域字段及类型、原始/规范化统计时间、选中的标准单位、
最终词组和完整查询写入 `SourceAcquisitionAttempt.details.search_query_plan`。
`RowSearchAttempt.query` 和搜索结果列表继续按原契约保存，结果为 0 时也必须可审核。

## 完整性边界

本决策只改变候选发现，不改变证据准入：

- 工作簿直链仍优先，失败后才搜索；
- RowContract 的 `required_matches` 仍包含指标名及全部非空级别、地域、统计时间、范围和行业约束；
- 模型合成与独立核验仍必须检查完整 RowContract、单位和口径，搜索摘要不能直接成为正式证据；
- 网页主内容、附件下载与解析、来源快照、人工审核链接和搜索降级展示保持不变。

因此，查询更宽只提高候选召回率，不降低最终结果的验证门槛。

## 验证

- 单元测试覆盖区县优先、仅经济区可用、年/年月/年季度规范化、可选标准单位和噪声字段排除；
- 采集集成测试确认查询计划进入来源获取审计；
- 新全量任务必须从原始空表重新规划，旧 v1.1.0 结果与搜索缓存不得复用；
- 部署后首批搜索应同时记录查询及结果数，用于与 v1.1.0 的 13/13 零结果基线比较。
