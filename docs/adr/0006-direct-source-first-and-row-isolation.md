# ADR-0006：采集直链优先、来源上下文复用与单行隔离

## 状态

已接受，2026-08-24。本文取代 ADR-0004、ADR-0005 及 V2.4 文档中“每个 RowContract 必须先搜索、再补入工作簿直链”的旧规定；未被本文修改的双阶段模型、全局并发和金标隔离规定继续有效。

## 背景

工作簿中的采集链接是当前行明确提供的业务来源，不是普通搜索候选。现有实现却总是先调用 SearXNG，再把直链放到候选末尾。`ai_index` 第 1955 行因此忽略 GitHub Innovation Graph 官方 CSV 中 `EC,2021,Q3` 的精确记录，转而采用搜索结果中的中国数据。该行为同时降低准确性、增加搜索等待，并浪费相同来源的重复下载和解析。

本地仅有 `Qwen3.8-27B-6bit`，OMLX 全局并发固定为 1。系统仍需为每一行串行执行 `SYNTHESIZE` 与 `VERIFY` 两次独立模型请求，禁止多行批处理和跨行对话会话。

## 决策

### 1. 直链优先的采集路由

每个进入采集管线的 RowContract 必须完成并审计一种来源获取路由：

```text
存在采集链接
  -> 规范化、获取、解析并缓存来源
  -> 用 RowContract 做确定性匹配
     -> 唯一匹配且包含目标数据：DIRECT_LINK，禁止搜索
     -> 获取失败、目标缺失或匹配歧义：记录原因后 SEARCH_FALLBACK
不存在采集链接
  -> SEARCH_FALLBACK（NO_DIRECT_SOURCE）
```

搜索是有条件的降级能力，不再是每行固定前置步骤。`RowSearchAttempt` 只在实际调用 SearXNG 时创建。

### 2. URL 规范化与确定性匹配

- 在 SSRF 校验和重定向复核不变的前提下，将已知展示链接规范化为可下载资源，例如 GitHub `blob` URL 转换为对应 raw URL。
- 清理 fragment 和无业务意义的跟踪参数；保留请求 URL、规范化 URL和最终 URL，确保可审计。
- CSV/TSV 等结构化来源先以程序规则解析。日期、季度、地域和字段别名必须由版本化规则匹配，例如 `2021Q3 -> year=2021, quarter=3`、`EC -> iso2_code=EC`。
- 只有唯一匹配行可作为确定性证据；零匹配或多匹配不得猜测，必须进入搜索降级或未解决状态。
- 模型不得放宽或重新解释 RowContract 的明确地域、日期、口径和单位约束。

### 3. 来源复用与行上下文隔离

- 相同规范化 URL 的网络响应和解析产物持久化为不可变 `SourceSnapshot/SourceContext`，以 URL、校验信息和内容哈希去重；跨任务重启也可复用。
- 多行引用同一来源时，只复用原文、结构化索引和面向当前 RowContract 生成的有界证据切片，不复用其他行的候选、结论、提示词或会话历史。
- 每次模型请求只包含一个 RowContract。每行继续串行执行两个新请求：`SYNTHESIZE` 完成后，`VERIFY` 以新的请求上下文接收同一行证据和候选。
- 不创建跨行聊天会话。OMLX 前缀缓存仅作为可观测、可回退的性能优化；关闭缓存不得改变业务结果。
- 调度可将相同来源的 unit 相邻执行以提高本地前缀缓存概率，但不得改变任务优先级、单行原子提交和全局模型并发 1。

### 4. 审计与状态

新增行级 `SourceAcquisitionAttempt`，至少保存：

- `route`：`DIRECT_LINK` 或 `SEARCH_FALLBACK`；
- 输入、规范化和最终 URL；
- 状态、失败/降级原因码、开始和结束时间；
- 内容哈希、缓存命中、媒体类型和解析器版本；
- 结构化匹配条件、匹配数量、定位信息和 SourceContext 标识。

推荐原因码包括 `NO_DIRECT_SOURCE`、`DIRECT_FETCH_FAILED`、`DIRECT_PARSE_FAILED`、`TARGET_NOT_FOUND`、`AMBIGUOUS_MATCH` 和 `DIRECT_SOURCE_INCOMPLETE`。生产提交门禁要求有一条成功的采集路由、严格的 `SYNTHESIZE -> VERIFY` 两次模型调用和确定性校验；不再要求每行都有搜索记录。

Web 端使用中文展示“直链获取/搜索降级”、缓存命中和降级原因，不直接展示原始 JSON。

对于输入行没有 `source_url` 的场景，搜索候选 URL 只能先作为 Evidence 保存。只有以下任一门禁通过后，实际支持结果的网页或附件 URL 才能进入 `source_url`：

- `VERIFY` 批准结果并明确引用该来源；
- 人工批准/修正结果，并选择或填写与修正值对应的来源。

模型复核失败、值仍为空、仅有搜索摘要、来源未被引用或存在多个无法确定主来源时，不得提前回填 `source_url`。人工提交时若结果值已解决但 `source_url` 仍为空，系统仅在已选证据 URL 唯一时自动补入；否则阻止提交并提示审核人选择或填写。

### 5. 历史数据修复边界

先生成只读影响预览：筛选存在输入采集链接、但最终采用其他来源或缺少直链采集审计的历史结果，并展示旧值、直链唯一匹配值、来源和差异。未经用户确认不得批量覆盖历史结果。生产修复流程不读取或比较金标。

## 后果

正面影响：优先使用用户明确提供的权威来源；相同来源只下载和解析一次；减少不必要的搜索等待；避免跨行会话污染；可准确区分直链成功、搜索降级和缓存命中。

代价：需要新增采集路由审计、持久化快照、URL 适配器、结构化匹配规则、迁移和历史影响预览；旧任务保持可读，但不会伪造新的采集路由审计。

## 验证

1. 直链唯一匹配时搜索调用数为 0，仍有且仅有两次模型调用。
2. 直链获取失败、无目标数据或匹配歧义时，仅触发一次该行搜索，并保存明确原因。
3. N 行共享一个 URL 时网络获取和解析各一次、模型调用 `2N` 次，任一提示词仅含一个 RowContract。
4. GitHub `blob` 链接可规范化为 raw CSV；`EC + 2021Q3` 唯一匹配 `125033`，不得解释为中国。
5. 缓存开启/关闭的业务结果一致；OMLX 实测最大在途请求始终为 1。
6. 生产包、运行配置、数据库和提示词继续通过金标隔离扫描。

## 本机缓存基准

2026-08-24 在任务安全暂停后，对本机 OMLX 连续发送两次完全相同的 43-token 单行请求。两次均返回正确 JSON，耗时分别为 2.060 秒和 1.557 秒，但服务返回的 `cached_tokens` 均为 0。该小样本不能证明长上下文一定无缓存，却证明当前部署不能把前缀缓存命中当作可用契约。因此本轮主要收益来自 URL/内容/解析产物的持久化复用；相同来源相邻调度和稳定提示词前缀只保留为机会性优化，并持续记录真实 `cached_tokens`。
