# ADR-0005：P0 状态、吞吐、审核与金标边界

## 状态

已接受，2026-08-24。

## 背景

当前平台已打通采集、证据、审核和 Excel 导出链路，但三类问题会直接增加人工工作量或误导验收：

1. worker 执行成功、业务字段已解决和审核完成尚未完全分离，空值可被成功口径掩盖。
2. 每行独立的来源获取审计和固定双阶段模型复核是必须保留的质量契约；本地只有 `Qwen3.8-27B-6bit` 且全局并发只能为 1。来源顺序按 ADR-0006 修订为采集直链优先、必要时逐行搜索降级；吞吐优化必须避开跨行结论复用、模型批处理/并发和减少模型调用次数。
3. 审核以逐行人工决策为主，自动通过、安全批量操作和“已确认无法填值”缺少完整语义。

历史数据存在金标工作簿，可供测试和项目验收对照；但每次真实采集都是新任务，生产项目不能知道或假设金标存在。

## 决策

### 1. 实施顺序固定

实施前置门禁是先将旧 `gold collector`、金标配置和对照逻辑移出平台生产包/运行时，改为独立验收工具并加入 CI 边界扫描。该门禁不是新的 P0 业务阶段。

```text
P0-3 状态语义
  → P0-2 吞吐与可恢复性
  → P0-4 异常审核效率
```

后一阶段不得依赖模糊的前一阶段语义。特别是审核策略必须基于已稳定的业务解决状态，不基于 worker `SUCCEEDED`。

### 2. 状态正交建模

- `execution_status` 记录 worker 执行生命周期。
- `resolution_status` 记录目标组是否 `RESOLVED/PARTIAL/UNRESOLVED/CONFLICT/INVALID`，由确定性校验器计算。
- `review_status` 记录 `UNREVIEWED/AUTO_APPROVED/APPROVED/CORRECTED/CONFIRMED_UNRESOLVED/REJECTED/SKIPPED`。

任务统计和 UI 为三类状态分别展示计数和分母。`SUCCEEDED + null` 不得计入已解决。

### 3. 逐行采集路由、来源缓存与固定双阶段模型

- 每个 RowContract 建立自己的 `SourceAcquisitionAttempt`。有采集直链时先直接获取并做确定性唯一匹配；仅在无直链、获取失败、目标缺失或匹配歧义时建立本行 `RowSearchAttempt` 并调用 SearXNG。
- 可以通过 `SourceSnapshot` 和 `UnitSourceLink` 复用相同 URL/内容的下载与解析产物，但每行重新建立证据定位、契约匹配、提示词和结论；搜索响应和行结论不得跨行复用。
- discover/fetch/parse/synthesize/verify/validate 分阶段持久化，各自具有幂等键、attempt、lease、heartbeat、`next_attempt_at` 和资源上限。
- OMLX 只使用 `Qwen3.8-27B-6bit`，全局并发为 1，禁止多行批处理和并发。
- 每行固定串行执行两次独立请求：第一次综合候选，第二次使用新上下文复核证据与候选。结构化来源也不跳过。

### 4. 例外优先审核

- 版本化 `ReviewPolicy` 只能对低风险且经确定性闭环验证的结果产生 `AUTO_APPROVED`，并按政策抽样。
- 人工队列默认只显示异常、冲突、低置信、抽样和需要业务决断的结果。
- 重试耗尽的 `FAILED_FINAL` 是已执行异常，优先进入人工队列并展示最终错误与完整 attempt；只能完整补录、确认无法解决或驳回重采，禁止直接批准。
- 批量操作分为 filter snapshot preview 和 expected-version apply；冲突、无效、未执行或在途结果不得批量通过。
- `CONFIRMED_UNRESOLVED` 允许经调查确认无法安全填值的项保持空值，但必须进入正式导出附带的未解决报告。

### 5. 金标与平台隔离

- 金标仅由项目外部的测试/验收比较器在平台运行完成后读取。
- 生产包、API、worker、模型 prompt、运行配置和数据库不得包含金标文件路径、文件名、collector 或衍生值。
- 冻结 Fixture 只能是历史原始来源和业务配置，不得从金标反向生成。
- 旧 `gold collector` 验收仅作平台管线/工作簿重建历史回归记录，不作为采集准确率证据。
- `preserve` 是当次业务配置或用户授权语义，不得通过金标中数据未变化来选择或生成该策略。

## 后果

正面影响：进度与验收口径更准确；优先使用明确采集来源并减少不必要搜索，在不减少模型调用的前提下降低重复下载/解析并提高恢复能力；人工工作聚焦到真正例外；金标泄漏不再造成虚假验收。

代价：需要数据迁移、API/UI 契约更新、快照存储与恢复扫描，并对 ReviewPolicy 设置持续抽样和停用机制。

## 验证

1. P0-3、P0-2、P0-4 各自通过对应的单元、集成、API/UI 和迁移测试后才进入下一阶段。
2. 使用历史数据时，平台先在无金标权限的环境中完成运行，外部比较器再计算记录集与字段语义指标。
3. CI 扫描生产包、运行配置和 prompt，阻止金标文件名、路径或 collector 进入运行时。
