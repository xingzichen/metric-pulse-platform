# ADR-0010：平台不处理工作表边界

- 状态：Accepted / Implemented
- 日期：2026-08-24
- 适用范围：工作簿分析、视觉识别、任务规划、采集、审核与导出

## 背景

原通用工作簿分析会根据字段名和空值率为未知工作表推断目标字段。这种能力不适用于已经
明确由人工或其他程序负责的数据集，否则平台会重复采集、占用唯一的本地模型通道，并可能
与真正的数据维护方同时写入同一个工作表。

以下工作表依赖人工处理，本平台不再处理：

- `AI_news`
- `gpu_chip_performance`
- `ai_person`
- `ai_computing_power`

以下工作表已有独立自动采集程序处理，本平台不再处理：

- `ai_model_permission`
- `aigc_reg_i`

## 决策

1. 以稳定机器名片段维护代码级排除清单；不依赖可能被 Excel 31 字符上限截断的完整标题。
2. 工作簿分析仍展示这些工作表及预览，但固定写入 `mode=excluded`、空描述/目标/业务键、
   `excluded=true` 和结构化排除原因。
3. 排除表不需要字段确认，也不触发视觉模型识别；视觉识别结果记录“已跳过”和业务原因。
4. 默认任务创建只选择存在目标字段的工作表，因此排除表不会进入任务配置。
5. API 和任务服务同时执行强制范围校验。即使调用方绕过前端手工提交目标字段，也必须在
   创建任何采集单元之前以 422 拒绝。
6. 排除表不产生 RowContract、采集单元、来源请求、搜索、模型调用、审核项或导出更新；
   正式导出必须保留其原始内容、公式、样式和尺寸。
7. 前端用中文显示“依赖人工处理”或“由既有自动采集程序处理”，不直接展示
   `excluded` 等内部英文模式值。
8. 这是业务所有权边界，不是可由环境变量临时开启的功能开关。重新纳入任何工作表必须先
   更新需求、ADR 和代码清单并完成回归。

## 与现有设计的关系

- 取代通用识别为上述工作表推断目标字段的行为。
- 取代视觉模型可覆盖上述工作表字段角色的行为。
- 不影响 `ai_index`、GitHub 月度 Top 10、福布斯年度 AI 50 及其他仍在平台范围内的工作表。
- 不改变 OMLX 全局并发 1、逐行固定双模型、审核门禁和生产金标不可见边界。

## 验收

1. 原始空表的 6 个排除工作表全部显示结构化原因、目标字段为空且无需确认。
2. 默认全量任务不包含这 6 个工作表，规划数量从 10,860 降为 10,775。
3. 手工 API 配置任一排除工作表返回 422，数据库中不产生对应记录或单元。
4. 视觉预检成功或失败都不请求排除表预览/识别，排除状态不会被覆盖。
5. 任务记录、采集审计、模型调用和审核队列中不存在上述机器名。
6. 导出文件中的排除工作表与原始输入逐单元格和结构保持一致。
